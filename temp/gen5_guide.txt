This document provides procedural and reference information for the Gen5 OLE 
Automation interface. 
To get the most out of this document, you should be familiar with: 
 Microsoft Windows programming environment 
 Microsoft Component Object Model (COM) 
 Microsoft OLE Automation (Automation) 
 BioTek Gen5 Application 
1.1 Overview 
Gen5’s OLE Automation interface is designed for customers needing to integrate 
Gen5 and BioTek readers into an automated system. Gen5 can function as an OLE 
Automation server to provide an OLE Automation client application access to most of 
its features. 
The client application can, for example, use Gen5 to: 
 Create a new experiment 
 Perform a read 
 Export results 
 Print a report 
Gen5 also provides basic reader commands, such as 'open door', 'close door', etc... 
Gen5 can be controlled from any programming language that supports OLE 
Automation including C++, Visual Basic, C#, applications that include VBA (Visual 
Basic for Applications) such as Excel, and even scripting languages such as VBScript 
and JScript. 
The user must refer to the Microsoft OLE/ActiveX documentation and should have a 
good knowledge of OLE mechanisms prior to using this document.

1.2 Gen5 Automation Basics 
1.2.1 Gen5 Automation Interfaces  
Gen5 supports the following automation interfaces: 
 Application 
 Experiment 
 Plates 
 Plate 
 PlateReadMonitor 
 MonoCalTestMonitor 
 SystemTestMonitor 
1.2.1.1 Application 
The Application interface represents a single instance of Gen5. The 
Application interface supports the ability to configure a single reader. The 
Application interface can be used to create an experiment or open an existing 
experiment. 
A client application may maintain multiple Gen5 Application interfaces to 
control multiple readers, however, each reader must be uniquely configured. 
For example, only one Application interface may configure a reader on COM1. 
Any reader related functions should not be called while a read is in progress. 
1.2.1.2 Experiment 
The Experiment interface represents a Gen5 experiment. The Experiment 
interface is created when either a new experiment is created or an existing 
experiment is opened.  All experiments are associated with a protocol, which 
determines certain characteristics of the experiment and its individual plates.  
At any given time, a single Gen5 Application interface is limited to a single 
Experiment interface.   
An Experiment should not be closed while a read is in progress. 
1.2.1.3 Plates 
The Plates interface represents the collection of plates of a Gen5 experiment. 
The Plates interface is a property of the Experiment interface. Creating a new 
experiment will automatically create one or more plates. The number and 
type of plates created are dependent on the protocol type. 
In general, plates can be programmatically added or deleted as required by 
the application. The exception is an experiment created with a Multi-Plate 
Assay protocol, or Calibration protocol. In a Multi-Plate Assay experiment, 
plates cannot be added or deleted. In a Calibration experiment, calibration 
plates cannot be added or deleted but the "Other Plates" can be.

The Plates interface derived from Experiment interface must be released 
before the experiment is closed. 
 
1.2.1.4 Plate 
The Plate interface represents a single plate of an experiment. The Plate 
interface is a single element of the Plates interface. 
The Plate interface provides methods for reading a plate, printing results, 
exporting results, etc. 
While a plate is being read you should not delete it, perform an export, or 
print a report for that plate. 
The Plate interface derived from the Plates interface must be released before 
the experiment is closed. 
1.2.1.5 PlateReadMonitor 
The PlateReadMonitor interface is used to maintain the status of a read 
operation performed on a specific plate. The PlateReadMonitor interface is 
created when a read operation is successfully initiated. 
The PlateReadMonitor interface can be used to monitor the progress of a 
read. If errors occur during a read, then the PlateReadMonitor interface 
provides information regarding the errors. 
1.2.1.6 MonoCalTestMonitor 
The MonoCalTestMonitor interface is used to monitor the status of a mono 
calibration test. The MonoCalTestMonitor interface is created when a mono 
calibration test is successfully initiated. 
Note: The mono calibration test is used by internal BioTek processes. 
1.2.1.7 SystemTestMonitor 
The SystemTestMonitor interface is used to monitor the status of a system 
test. The SystemTestMonitor interface is created when a system test is 
successfully initiated. 
1.2.2 Error Handling 
1.2.2.1 Generality 
Gen5 uses exceptions to notify the client application of errors. All calls to 
Gen5 should be enclosed in a try catch block to catch any errors thrown by 
Gen5. The exception will contain an error code and a text description of the 
error that caused the function to fail. The error codes are defined in 
BTIStatusCodes.h. It is highly recommended for the programmer of the client 
application to use the constants defined in this file rather than the numerical 
error codes. 
In case of multiple errors, only the first (considered as significant) is 
forwarded to the OLE Client application

Receiving an exception indicates that the operation failed or was not executed 
at all, typically because input conditions were not met. 
1.2.2.2 Read Process 
In case of a read operation, all the errors that have occurred are available in 
the error collection of the PlateReadMonitor interface. 
The error collection may not only include errors that apply to the read but 
also errors that occurred while compound operations were being executed 
(ex: auto-save, print…). 
To know the status of the read, the OLE Client application needs to look at the 
final status of the Plate. 
1.2.2.3 Critical database errors 
In case of critical database errors (not only occur when Gen5 is configured to 
store experiment & protocol files in the SharedDB database but in all cases), 
the error is forwarded to the OLE Client application (like any other). 
The reset of the connection is not done immediately but when the next 
method potentially including database operations is started. 
If the error could not be cleared properly, the same error message is 
forwarded to the client application and the operation is aborted 
1.2.3 Storage Options 
Each Gen5 installation can be configured to use either database storage or 
Windows® file system storage for protocols and experiments. Pathnames for 
these two options have unique properties and cannot be used out of context. 
1.2.3.1 Database Storage 
When Gen5 is configured to use the database for storage, the file paths used 
for Experiments and Protocols must be database paths, for example 
"DB:\Protocols\example1.prt". 
1.2.3.2 Windows File System Storage 
When configured to use the Windows file system, the file paths must be 
standard Windows file paths, for example "C:\Protocols\example1.prt". 
 
1.2.3.3 Multiple instances storing data in the same database 
When Gen5 is configured to use the database for storage, several instances 
(same or different PCs) may save data in the same SharedDB databases with 
no restriction: 
 Same folders can be accessed from multiple instances 
 Autosave/Autoname is supported 
Possibly save performances may decrease with the number of instances being 
used at the same time.

1.2.3.4 Read-only files 
Read-only files are supported via OLE Automation with the same limitations 
than in instanced started manually: 
 Read-Only files cannot be re-saved with the same name/path 
(Experiment.Save & AutoSave processes fail) and an alternate location 
must be specified (with Experiment.ReSave). 
Please note than an experiment file can be read-only for the following 
reasons: 
 It was opened after another instance opened it in Read/Write mode 
 A database error occurred and the file could not be re-opened in Read-
Write mode after the database error was cleared (ex: it was opened by 
another instance in Read/Write mode in the meantime) 
1.2.4 Protocol Options 
Individual protocols provide the following options. The Experiment interface 
provides properties to help the Automation programmer determine which 
options are defined for the current experiment. 
1.2.4.1 Save Options 
A protocol can be setup to automatically save the experiment following one or 
more events, including the reading of a plate. 
The Experiment interface also provides methods to the Automation 
programmer for saving an experiment. 
1.2.4.2 Auto-Output Options 
A protocol can be setup to automatically print and/or export results following 
the reading of a plate. 
The Plate interface also provides methods to the Automation programmer for 
printing or exporting results. 
1.2.5 Security 
If the Gen5 product type is Gen5 Secure or Gen5 Clinical and the system 
administrator requires login in OLE Automation (see System > Security > 
Login), then the following behavior applies. 
The Gen5 server will prompt for a login when any of the following methods is 
invoked and no previous login has occurred for the current life cycle of the 
Application interface. 
 
 Application.NewExperiment 
 Application.NewExperimentEx 
 Application.OpenExperiment 
 Application.BrowseForFile

1.3.5 Visual C++ (Using MFC Wrapper Class) 
To use Gen5 from an MFC C++ application use Visual Studio’s Class wizard to 
create a wrapper class to encapsulate the Gen5 Automation interface. The 
generated classes will create Get and Set methods for the interface 
properties. It also creates Set methods for read only properties. This can be 
misleading, because read-only properties cannot be set and calling a Set 
method on a read-only property will always fail. 
You can also use Visual Studio’s COM smart pointers with an MFC application 
instead of generating a wrapper class. 
1.3.5.1 Create a New Visual C++ MFC Project 
1.3.5.2 Add the Gen5 Wrapper Classes 
From the Project menu, select Add Class… 
Select MFC Class From TypeLib 
Using the registry option, select Gen5 from the Available Type Libraries,  
or using the file option, browse to the Gen5 Executable. 
Add all the interfaces to the Generated Classes. 
You may customize the Names of the classes and the files that they will be 
placed in.  By default, each class will be placed in a separate file. For 
convenience, you may rename the file for each class to the same name. The 
Sample MFC application provided by BioTek uses Gen5Wrapper.h for all of the 
Interface Classes, however you are not required to do this.  
1.3.5.3 Using Gen5 In Your Application 
To use automation, your application must call either AfxOleInit() or 
OleInitialize(). Note: if you use OleInitialize() you must also use 
OleUninitialize(). See MSDN documentation for more details. 
If you use AfxOleInit(), a not responding dialog may be displayed if a method 
doesn’t return after a default timeout period. Generally, this should not a be a 
problem with Gen5. however, there are some situations when Gen5 is waiting 
for a response from a reader, that will cause a function to take several 
seconds to return and may exceed the default timeout period.  It is most 
likely to occur with the PlateReadMonitor::GetReadInProgress () because this 
will generally be called repeatedly during a read but it can happen with any 
method.  To avoid problems disable the "not responding" dialog by using the 
following calls: 
AfxOleGetMessageFilter()->EnableNotRespondingDialog(FALSE); 
PlateReadMonitor::GetReadInProgress(); 
AfxOleGetMessageFilter()->EnableNotRespondingDialog(TRUE);

The Close method will close the opened experiment unless the 
experiment is in a state where it cannot be closed immediately (for 
example, if a read is in progress).   If the experiment is in a modified 
state and the CreateTempFileIfUnsavedExperiment property of the 
Application is true or a database error was detected, the modified 
experiment is saved into a temporary file on the hard-drive. In this 
case, an OLE exception is forwarded to the calling process.

does it prompt the user to save. 
Once the Close Method is called the Experiment object that it is called 
on is no longer valid and should be discarded, also any Plates or Plate 
objects that were attached to this object will be invalid and should also 
be discarded.

Settings>\All Users\Application Data\BioTek\Temp" folder using the 
following naming convention: 
Tmp_<Name>_<Index>.xpt 
Where: 
<Name> is the name of the experiment 
<Index> is a unique 4-digit index 
void Close() 
 
Notes:

The returned string is an XML string that contains a description of the

The syntax is the following: 
<BTIDataSetInfo Version="[Version]"> 
  <DataSet Type="[Type]" Name="[Name] "> 
    <RawData>[true/false]</RawData> 
    <Valid>[true/false]</Valid> 
    <Available>[true/false]</Available> 
    <Dimensions>      ! section optional 
      <[Name1] First="[First1]" Last="[Last1]" /> 
      … 
    </Dimensions> 
    <CalculationStatus>[Status]</CalculationStatus>  ! only for calculated data 
    <CalcLogEntries/>    ! section optional 
  </DataSet> 
</BTIDataSetInfo> 
 
Where: 
[Version] Is always 1.00 
[Type] Indicates the type of data set. 
Can be PlateResult, PlateImage, Temperature, 
FormulaList, Validation, CutOff, Curve 
[Name1] Is the name of a parameter to pass to 
GetDataSetResult (see below). 
In general, Gen5 supports the following dimension 
parameters: 
- PlateIndex (applicable to Multi-Plate per Assay 
protocols and to labwares) 
- KinIndex (applicable to kinetic reads) 
- WavelengthIndex (applicable to spectrum reads) 
- HzScanIndex & VtScanIndex (applicable to area 
scan reads) 
- SliceIndex (applicable to Z Stack imaging reads) 
- MontageRowIndex & MontageColIndex 
(applicable to Montage imaging reads) 
 
Temperature data sets support the following 
dimensions: 
- PlateIndex (applicable to Multi-Plate per Assay 
protocols and to labwares) 
- ROIIndex (applicable to multi-beacon reads) 
- KinIndex (applicable to kinetic reads) 
- InWellMatrixCol & InWellMatrixRow (If timing is 
per well; applicable to area scan reads and 
Montage imaging reads) 
[First1] Is the lowest acceptable value 

=== PDF PAGE 69 ===
 | Gen5 OLE Automation Programmer’s Guide 
| 69  
[Last1] Is the highest acceptable value 
Any parameter specified in the Dimensions section 
and that has a Last value greater than 1 must be 
specified in the call to GetDataSetResult (see 
below) 
The Dimensions section is omitted when there is 
no variable dimension for this data set 
[Status] Indicates the progress of data reduction of this 
data set 
Can be: 
 NotCalculated: only for steps that are 
skipped because of a validation step 
 Paused (only for data produced by an image 
processing or analysis step) 
 InProgress: A data set is considered as 
InProgress as soon as a data reduction 
process is started. This step will be actually 
calculated once the previous steps are 
completed. 
 Completed 
 
Notes: 
- PlateResults and PlateImage data sets also include a TimeStamping 
token that can be Plate or Well. 
- Temperature data sets also include a MeasurementType token that 
can be Plate or Well. 
- A data set is invalid if its definition is incorrect. For example, a 
transformation on 405 becomes invalid after the 405 filter has been 
changed to 450. 
You cannot query results for an invalid data set. 
- A data set is not available if its structure has not been created 
already. 
You cannot query results for an unavailable data set.

2.4.2.38 DisableKeepReadProcessGoingUntilCalculationsCompleted 
Changes the way Gen5 manages data reduction during the read. 
void DisableKeepReadProcessGoingUntilCalculationsCompleted () 
By default, Gen5 executes all defined data reduction steps during the 
execution of the read process and the PlateReadMonitor interface 
keeps returning ReadInProgress=true for some time after the read is 
actually completed by the reader. 
If the client application needs to retrieve the control on a plate as soon 
as possible after the completion of the procedure, then it should call 
the DisableKeepReadProcessGoingUntilCalculationsCompleted method 
before invoking any of the StartRead methods. 
In this case, only the Imaging analysis and processing steps that apply 
to raw data will be executed during the read, unless an automatic 
output (report, export, images or videos) is programmed. 
Once the ReadInProgress is false, the OLE client application can 
monitor the progress of data reduction with the Plate.CalculationStatus 
property.
